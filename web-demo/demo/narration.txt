TestPilot helps developers check a code change. It writes tests for the functions the change touched, runs them, and reports what it found. This page replays two recorded runs. The first one starts with a small change to a clamp function, which keeps a number inside a range. The verdict comes first. The generated tests found a real bug: the function swaps its low and high limits, so every value in range comes back as the high limit. Next, the tests TestPilot wrote for that change. Then the run. The tests fail on the changed code. TestPilot keeps those failures, because they point at the bug. Last, the check against the fixed version of the code. The same tests pass once the limits are the right way round. The second example is harder. Here the generated tests pass, even though a bug remains. The bug is in the median function. For a list with an even number of items, it returns one middle value, not the average of the two. The generated tests only use odd-length lists, so they all pass. A separate boundary check, written by hand, uses an even-length list. It fails on the same code, and passes after the fix. Each result has a download for the exact patch, the case record, and the full log, so every line can be checked. Nothing here calls a model. The replies were written ahead of time, and the test runs were recorded, as the label under the verdict says. That is the whole loop: a change, generated tests, a run, and a check against the fix.
