# Independent paired-revision receiving

This receiver uses authored negative-bucket and identity-drift inputs with real local Git repositories, actual CLI/API calls, and the existing retained-suite pytest collector. It was frozen from the public contract before candidate source access.

The actual CLI proves two generated fail-to-pass witnesses across non-ancestor commits, while preserving raw committed export-ignore/export-subst data, executable mode, dirty files, index, refs and saved report bytes. Reversing those commits yields after_failed. Separate API cases show that an existing-suite failure is not a generated witness, changed parametrized node identities are inconclusive, and a conflicting second tree is refused before the first tree can execute. Existing/inside-repository output destinations are preserved.

The first test had a receiver-only missing explicit import of importlib.util. Its original baseline and candidate logs remain unchanged: the candidate's three CLI/report cases passed, while three API methods stopped at that import. The successor adds only that import; removing the line recovers the exact original test. Its affected baseline methods fail because the capability is absent. The first successor candidate attempt stopped on ENOSPC during fixture creation; this is retained as an environment boundary. After compressing only the receiver's own verified metadata copies, the same three methods passed. All six scenarios are qualified across those original and affected runs, not misrepresented as one full six-pass successor execution.

The portable test derives source from imported testpilot, uses disposable temporary directories and a sibling fixtures/regression_receiving.json file. An optional TESTPILOT_RECEIVING_PYTHON selects a genuinely installed pytest interpreter; otherwise it uses the current interpreter. TESTPILOT_RECEIVING_EVIDENCE optionally retains full results. Repository CI should run the complete successor with its declared dependencies.

receiving.json pins source/test/fixture identities and precise outcomes. original-peer-evidence.zip contains every original protocol, test, fixture, run log, source freeze and raw result, including receiver/environment failures. Each archived member was read back byte for byte. No production edits, model invocation, provider interaction or security-isolation claim is made.
